# 千駄木ちゃんこ祭りアンケート

`index.html` を入口にした、スマートフォン向けのアンケートフォームです。

回答は Google Apps Script のウェブアプリを経由して、指定の Google スプレッドシート（gid=0）へ保存します。Apps Script のソースは `Code.gs` です。

## ファイル

- `index.html`：フォーム本体
- `styles.css`：デザイン
- `app.js`：入力チェックと送信処理
- `thank-you.html`：回答済み表示と壁紙プレゼント
- `thank-you.js`：回答済み判定
- `wallpaper.html`：3つの作品から1デザインを選び、端末別サイズを受け取るページ
- `wallpaper.js`：1デザインを確定し、iPhone・Android・PC版を何度でも保存できる処理
- `wallpaper-maker.html`：非公開で使う壁紙トリミングツール
- `wallpaper-maker.css` / `wallpaper-maker.js`：トリミング画面と画像処理
- `assets/chanko-wallpaper.png`：回答者向け壁紙
- `assets/wallpapers/`：「茜の千駄木」「蒼流の庭」「朱映の杜」それぞれのiPhone・Android・PC版（計9枚）
- `Code.gs`：Google スプレッドシートへの保存処理

`app.js` の `SCRIPT_URL` には、デプロイ後のウェブアプリURLを設定します。

回答完了後はCookieと`localStorage`へ回答済み状態を1年間保存し、同じブラウザからの再回答を止めます。ブラウザのデータを消去した場合、シークレットモード、または別端末からの回答までは識別できません。

壁紙は一度選択すると別デザイン・別端末版へ変更できません。同じ壁紙の再保存は可能です。

## クーポン総括管理・利用店舗

- `management.html`：「千駄木二丁目町会商店街総括管理サイト」の入口。店舗と責任者の登録・編集、発行済み／未使用クーポンの一覧・件数確認、一括無効化を行います。
- `stores.html`：購入者向けの利用可能店舗一覧・Google マイマップ。店舗一覧は `加盟店` シートの公開済み店舗から自動取得します。
- `coupon.html`：購入者向けクーポン。受け取った券を同じブラウザの `localStorage` に保存し、次回以降も開けます。別端末や閲覧データ削除後は復元できないため、URLのブックマークやスクリーンショットも勧めてください。
- `ManagementApp.html`・`StoresApp.html`・`coupon-wallet-app.html`：Apps Script の管理・店舗地図・購入者用の画面本体です。
- `coupon-issue-app.html`：Apps Script では `CouponIssue.html` として配置するQR発行画面です。`coupon-issue.html` が公開側の入口です。
- `coupon-redeem-app.html`：Apps Script では `CouponRedeem.html` として配置するQR確認画面です。`coupon-redeem.html` はカメラを扱う公開側の入口です。
- `staff-webauthn.js`：公開側ページで FIDO2/WebAuthn を実行するブリッジです。Apps Script の iframe 内ではなく、公開サイトのドメインでキーを使用します。
- `WebAuthnCrypto.gs`：Apps Script 上で登録キーの署名を検証するコードです。`Code.gs` と一緒に Apps Script プロジェクトへ追加してください。配布ライブラリのライセンスは `WebAuthnCrypto-LICENSE.txt` にあります。

ログイン権限は、総括管理サイトが `manager` のみ、QR発行が `admin`・`manager`、QR確認と使用済み処理が `admin`・`manager`・加盟店アカウントです。加盟店アカウントは発行・総括管理には使えません。Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」に `MANAGER_PASSWORD_TEMP` を追加し、総括管理専用の強いパスワードを設定してください。管理者IDは `manager` です。初回ログイン成功時、サーバーが SHA-256 ハッシュの `MANAGER_PASSWORD_SHA256` を保存し、平文の一時プロパティを削除します。パスワードをコードや GitHub に書かないでください。設定するまでは管理画面へログインできません。

店舗登録時は店名・責任者に加えて、その加盟店専用のログインID・パスワードを決めます。所在地、緯度、経度をそろえて「公開」にすると購入者向けの店舗一覧に表示されます。地図のピンは別途マイマップ側で登録します。責任者名とログイン情報は公開されません。登録データはスプレッドシートの `加盟店` シートに保存します。既存の登録店舗は管理画面からログイン情報を設定してください。未設定の店舗は読み取り画面にログインできません。

利用店舗ページの Google マイマップ埋め込みは API キーや Google Cloud の請求先設定を使用しません。一覧は `加盟店` シートから更新されますが、マイマップのピンは自動同期されません。店舗の追加・変更・非公開時は、マイマップ側のピンも手動で更新してください。マイマップは公開地図なので、登録するのは公開済み店舗の店名・住所・位置だけにし、責任者名、ログイン情報、クーポンDB、スプレッドシート全体を取り込まないでください。

`加盟店` シートは従来の9列を残したまま認証用の5列を追加します。パスワードの平文は保存せず、ソルト付きハッシュを記録します。初回の登録時に Apps Script のスクリプト プロパティへ `MERCHANT_PASSWORD_PEPPER` が生成されるため、削除しないでください。加盟店にはスプレッドシート本体の編集権限を渡さず、読み取り画面のアカウントだけを渡してください。

加盟店は `coupon-redeem.html` から自分のID・パスワードでログインし、購入者のQRまたはクーポンIDを確認・利用処理します。利用店舗名はログイン中の加盟店登録から決まります。`admin`・`manager` が確認・利用処理した場合は、店舗名の代わりにその運営アカウント名を記録します。加盟店だけがログイン後のアカウント設定で、現在のパスワードを入力して自分のIDまたはパスワードを変更できます。変更後は再ログインしてください。総括管理者は店舗編集画面からパスワードを再設定できます。パスワードを共有資料・QR・URLに記載しないでください。

従来の加盟店専用APIはそのまま加盟店専用です。新しい共通のQR確認APIでは、`admin`・`manager`・加盟店のどれもサーバー側で認証してから確認・使用済み処理を行います。各画面のログイン状態は公開側ページの `sessionStorage` に期限付きセッショントークンだけ保存し、強制再読み込み後はサーバーに再確認して復元します。パスワードは保存しません。明示的なログアウト、タブを閉じる、ブラウザのサイトデータ削除、別ブラウザ・別端末、サーバー側セッションの失効後は再ログインが必要です。

### アカウント画像とセキュリティキー

3つのスタッフ画面にログイン中のアカウント名・画像とログアウトボタンがあります。画像設定では写真の位置と拡大率を調整できます。ブラウザで小さな正方形の画像に圧縮してから、認証済みアカウント専用の Base64 データとして `アカウント画像` シートに保存します。他のアカウントの画像はこの画面から変更できません。ただし、スプレッドシート自体の編集者には画像データが見えるため、個人情報を含む写真には注意してください。

`manager` のセキュリティキーは管理画面から登録します。最初の1本を登録する前は従来のパスワード認証、登録後は総括管理・QR発行・QR確認のどの画面でも **パスワードと登録済みキーの両方** が必要です。初回登録後、古い manager セッションは無効になり再ログインします。2本目以降の登録では登録済みキーによる追加確認が必要です。紛失に備え、別の予備キーも登録して安全な場所に保管してください。すべてのキーを紛失すると通常の画面からは復旧できず、Apps Script の所有者による慎重な復旧作業が必要です。

登録画面では挿している YubiKey を選んでタッチしてください。WebAuthn の署名により「登録したキー」であることは検証しますが、現在の構成はメーカーの証明書（attestation）を検証しないため、**Yubico 製だけに限定する仕組みではありません**。公開サイトのドメインを変更すると既存キーが使えなくなる可能性があります。公開済みの古い Apps Script デプロイが残っていると、古い認証方式の入口になり得ます。新しい版のデプロイ後、不要な旧デプロイを確認・停止してください。

「全件無効化」は、画面に表示された時点の有効期限内・未使用券だけを一括で `無効` にします。実際に購入者へ渡したかどうかは記録されていないため、未配布の発行済み券も対象です。確認画面から実行までに対象券が変わった場合は処理を中止します。クーポン行は削除せず、店舗側の確認・利用処理では `無効` 券を拒否します。取消し機能はありません。

操作時は `クーポン操作履歴` シートへ券IDごとの開始・完了（または要確認）の履歴を追記します。操作ID、日時、操作アカウント、割引額、変更前後の状態も記録し、過去行を書き換えません。管理画面には直近100行を閲覧専用で表示します。Apps Script エディタで `setupCouponAuditProtection` を一度実行すると、既存の6列・既存行を残したまま追加列を作り、履歴シートを保護できます。保護の設定に失敗した場合、一括無効化は実行しません。

Google スプレッドシートの保護は通常の共同編集者による編集を制限するものです。ファイル所有者とスクリプト実行者まで編集不能にはできません。厳格な改ざん防止が必要な場合は、所有者権限の管理や別保存先へのバックアップも必要です。`クーポンDB` をシート上で直接変更した操作は、このサイトの操作履歴には残らないため、元シートの編集権限も限定してください。また、管理アカウントを複数人で共有すると、履歴の操作アカウントだけでは実際の操作人物を識別できません。
